Ejercicio guiado · Sin programar

Registrar "Aventura en Antioquia"

Un administrador desea registrar una película llamada Aventura en Antioquia. Piensa cada respuesta antes de revelarla.

1¿Qué información debe ingresar el administrador?
Los datos de Media: serial, título, sinopsis, URL, portada y año de estreno, además del género, el director, la productora y el tipo a los que pertenece.
2¿Qué módulo debe recibir la solicitud?
El módulo Media, porque es el que registra películas y series.
3¿Cómo se comprueba que el género existe y está activo?
El backend consulta el módulo Género antes de guardar: verifica que el registro exista y que su estado sea Activo.
4¿Dónde se almacenaría la película?
En la base de datos, a la que solo accede el backend.
5¿Qué respuesta debería recibir el cliente?
Una respuesta HTTP: la película creada si todo es correcto, o un mensaje de error si alguna regla no se cumple.
Conclusión

Media necesita relacionarse con los demás módulos, y el servidor debe comprobar las reglas antes de almacenar los datos.

¿Qué es REST?

Un estilo para diseñar la API

REST (Representational State Transfer) es un estilo arquitectónico para diseñar sistemas distribuidos. Sus características introductorias:

🔗
Recursos identificados por URL
Cada recurso tiene su dirección: /api/generos.
📨
Operaciones HTTP
Los métodos GET, POST, PUT y DELETE indican qué hacer con el recurso.
🧾
Representaciones de datos
El recurso viaja en un formato como JSON.
🔄
Solicitudes sin estado
Cada solicitud lleva toda la información necesaria; el servidor no depende de las anteriores.
Importante

REST no es un lenguaje de programación ni una biblioteca: es una forma de organizar la comunicación entre cliente y servidor.

¿Qué es JSON?

El formato en que viajan los datos

JSON es un formato de intercambio de datos ampliamente utilizado en aplicaciones web. Se organiza en pares clave-valor.

Un objeto · { }
{
  "id": 1,
  "nombre": "Acción",
  "estado": "Activo",
  "descripcion": "Películas con escenas de acción"
}
Un arreglo de objetos · [ ]
[
  { "id": 1, "nombre": "Acción", "estado": "Activo" },
  { "id": 2, "nombre": "Aventura", "estado": "Activo" }
]
Clave-valor

Cada dato tiene un nombre entre comillas (la clave) y un valor: "nombre": "Acción".

Tipos básicos

Texto "Activo", número 1, booleano true/false y null.

Objeto { }

Representa un registro: un género.

Arreglo [ ]

Representa una lista de registros: todos los géneros.

29 / 38 · Primer servidor · POST
Endpoint POST

Registrar un género

app.js · antes de app.listen()
app.post("/api/generos", (req, res) => {
  const { nombre, estado } = req.body;

  if (!nombre || !estado) {
    return res.status(400).json({
      mensaje: "Nombre y estado son obligatorios"
    });
  }

  if (!["Activo", "Inactivo"].includes(estado)) {
    return res.status(400).json({
      mensaje: "Estado no válido"
    });
  }

  const nuevoGenero = {
    id: generos.length
      ? Math.max(...generos.map(g => g.id)) + 1
      : 1,
    nombre,
    estado
  };

  generos.push(nuevoGenero);
  res.status(201).json(nuevoGenero);
});
req.body

Toma el nombre y el estado que envió el cliente en formato JSON.

Validación

Si falta un dato, o el estado no es Activo ni Inactivo, responde 400 con un mensaje.

nuevoGenero

Calcula el siguiente id: el mayor existente más uno.

generos.push()

Guarda el género en el arreglo: almacenamiento temporal.

201 Created

Responde con el código 201 y el género creado.
